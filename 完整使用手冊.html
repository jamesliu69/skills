適用於 Codex、Claude Code 與支援 Agent Skills 標準的程式代理。這份手冊整理安裝、呼叫方式、完整開發流程、41 個 Skills，以及 C# .NET Framework 4.8／WinForms 自動化機台專案的實務用法。

專案定位

不是「大量生碼工具」，而是可組合的工程紀律。

對齊需求

以逐題訪談、領域語言與 ADR，降低 Agent 誤解需求的風險。

建立回饋迴路

透過型別檢查、測試、可重現命令與 Code Review，讓 Agent 看得到執行結果。

控制複雜度

以深模組、測試 seam、垂直切片與工單依賴，避免快速累積技術債。

這套方法的核心是：保留工程師的控制權。Skill 只規範處理流程，不取代你對需求、架構、風險與驗證方式的決策。

安裝與初始化

每個 Repository 先完成一次設定。

Codex、Claude Code 或其他 Agent Skills 工具

npx skills@latest add mattpocock/skills
全域安裝位置：Codex、Claude、OpenCode、Copilot、Gemini 的 Matt skills 會同步到各自的全域 skills 目錄。更新後請重新啟動工具以清除 skill metadata 快取。
Matt- 只加在清單顯示名稱，原有 slash 指令名稱維持不變。

安裝時選擇 Matt-setup-matt-pocock-skills
呼叫：/setup-matt-pocock-skills，接著在專案內執行：

/setup-matt-pocock-skills

初始化項目

  • Issue Tracker：GitHub、GitLab、本機 Markdown 或自訂系統
  • Triage 標籤字彙
  • CONTEXT.md 與 ADR 的文件布局
  • AGENTS.md 或 CLAUDE.md 的 Agent Skills 區塊

AGENTS.md 或 CLAUDE.md
CONTEXT.md

   ├─ domain.md
   └─ triage-labels.md
docs/adr/

兩種呼叫模式

差異在誰能啟動 Skill。

User-invoked

必須由使用者手動輸入，例如 /to-spec、/implement。適合負責流程編排，避免每輪都增加模型上下文。

Model-invoked

模型可依任務自動選用，也可由其他 Skill 呼叫，例如 /tdd、/diagnosing-bugs、/code-review。

與其他 Skill 的關係

不同情境的建議用法

情境一：新增自動復歸功能

先釐清狀態、互鎖、允許條件與失敗原因，再拆成可獨立驗證的工單。

/grill-with-docs
/domain-modeling
/to-spec
/to-tickets
/implement

情境二：現場回報難解 Bug

先保留現場證據與重現步驟，不要直接猜測根因；建立可失敗的測試回饋迴路。

/diagnosing-bugs
/research
/tdd
/code-review

情境三：安全互鎖或危險動作

把安全前置條件、禁止條件、超時與人工介入寫成明確政策，再以測試覆蓋每個分支。

/grill-with-docs
/domain-modeling
/to-spec
/tdd
/code-review

情境四：狀態機或 UI 設計不確定

先用拋棄式原型比較狀態模型與操作流程，確認方向後再進入正式實作。

/prototype
/handoff
/to-spec
/implement

情境五：既有程式架構難以維護

先找出複雜度集中處與模組邊界，再制定小步驟重構計畫，避免一次大改。

/improve-codebase-architecture
/request-refactor-plan
/to-tickets
/code-review

情境六：測試不足或回歸風險高
